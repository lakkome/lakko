# Real-browser UI tests

```
npm run test:e2e            # headless, both browsers
npm run test:e2e -- --project=chromium
npm run test:e2e:ui         # the Playwright runner UI, for debugging one test
```

The first run needs the browsers: `npx playwright install chromium webkit`.
The audio fixtures are generated by `globalSetup` and gitignored; `ffmpeg` is
needed for the AAC one (a spec fails naming it if absent) and `node playwright/fixtures/make-assets.mjs --force`
regenerates both.

## What this layer is for

There are three test layers under `apps/web`, and they are not
interchangeable:

| Layer | Answers | Cannot answer |
|---|---|---|
| `src/**/*.test.ts` (vitest, node) | Is the rule right? | Anything about a component |
| `src/**/*.test.tsx` (vitest, jsdom) | Is the component wired to the right event, and is the tree the right shape? | Anything about a size, a position, real media, or an engine policy — see `src/test/ui.tsx` |
| `playwright/specs/*.spec.ts` (this) | What does a person actually get? | Anything needing a signed-in account or a service |

This layer exists because two of the defects the jsdom project covers are
reachable there only by PROXY, and a proxy can hold while the thing a person
met still happens:

* the voice bubble growing by ~28px when playback starts is asserted there as
  "the cascade resolves `min-height` to `var(--control-h)`" — a height set any
  other way satisfies that. Here it is two `boundingBox()` reads either side of
  a real press. With the defect restored: **23.2px**.
* the message time sitting below the recording's duration is asserted there as
  a parentage fact. Here it is a comparison of the two boxes' vertical centres.
  With the defect restored: **14.4px apart**.

## No login, no backend

Nothing here signs in or talks to a service: there is no test account and
entering a credential is forbidden. A spec opens `harness/index.html?case=<name>`
and gets one PRODUCTION component with canned props. `harness/cases.tsx` holds
the discipline that makes that worth measuring — in short, a fixture never
reproduces a component's markup, and the only things stood in for are the two
name-resolver contexts (`harness/context-stubs.ts`) and the network, replaced by
filing the media bytes through the hub's own `fileLocal`.

Three narrow observers exist so a spec can read what the DOM does not expose:
the `Audio` elements the page constructed, the count of `getUserMedia` calls,
and the count of `MediaRecorder.start()` calls. All three delegate to the
platform — the element, the stream and the encoder are real.

## Browsers

**Chromium** runs everything. **WebKit** runs the layout and menu specs; the
recording specs skip on it by name, because the microphone here is Chromium's
`--use-fake-device-for-media-stream` fed by `--use-file-for-fake-audio-capture`
and Playwright's WebKit has no equivalent.

## What is NOT covered here, and why

**The autoplay refusal.** The original "pressing play did nothing" defect was an
engine REFUSAL: `play()` was awaited behind the fetch, landed after the
handler's task, and was rejected with `NotAllowedError`. Neither headless engine
reproduces it. Measured in this session, with a real click and the deferred
`play()` as the first click of a fresh document:

* Chromium 153 with `--autoplay-policy=document-user-activation-required`
  (confirmed on the launched process's command line, and the only
  autoplay-policy switch present) **allows** it. Chromium's activation is
  sticky per document, so one click licences every later start.
* Playwright's WebKit 26.6 **allows** it too.

Restoring that defect therefore leaves the playback spec green, and the spec
says so in place. What the spec does cover, and jsdom cannot, is everything
between the press and the sound: a real engine, real AAC decoded, the source
attached, the clock advancing. The ordering property the activation rule turns
into a requirement is covered where it is decidable — in `voice-press.ts` and
in `VoiceBubble.test.tsx`.

**iOS and Android.** This is web only.

## One trap, recorded because it cost a rewrite

Chromium's fake microphone opens in a few tens of milliseconds; a real one takes
a few hundred. The "recording lost the start of the phrase" defect lives in that
window, so against the fake device's own timing the measured loss was 11–54ms —
inside the encoder's frame quantisation, and the test passed on a recorder that
was demonstrably losing audio. It only failed when the suite happened to run
enough workers in parallel to contend the device (330–463ms). A test whose
discrimination depends on the worker count is not a test, so the harness now
models a realistically slow device on request (`?gumDelay=`), which changes the
environment and not the product.
